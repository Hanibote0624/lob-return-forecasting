# V5：完整合成数据验证与数据产物检查

V5 在 V4 的运行入口与配置预检基础上，使用生成的 CSV 实际执行 Stage1–5，核对数据进入训练之前的完整准备过程。仍保留 GPU 训练路线，没有增加 CPU 训练方案，也没有复现或新增历史模型收益结论。

## 完成内容

- 新增 `scripts/check_synthetic_pipeline.py`：默认临时运行，也可指定新目录保留合成数据、阶段产物、日志和 JSON 摘要。
- 新增独立参考计算：逐行检查事件均价收益、无效标签、裁剪、训练统计、打包行、窗口端点和加载器批次。参考计算不调用生产标签、预处理或窗口筛选函数。
- 完整执行两个案例：基准案例，以及只修改验证/测试数据的案例。两者的训练统计必须一致，验证/测试产物必须发生变化。
- 新增 8 项集成/故障注入测试和 1 项中间价精度回归测试；与 V4 的 64 项测试一起，由本地检查及现有 CI 入口执行。
- 提供公开合成验证摘要，记录依赖版本、产物计数及源码指纹。合成 CSV、二进制产物和机器路径不进入交付仓库。

## 实际发现并修复的问题

**Stage2 隐式中间价舍入。** 原实现先将中间价四舍五入到三位小数，再计算未来收益。完整核对发现这会改变约定的事件均价收益目标。现在使用未舍入的 `float64` 中间价计算收益，原始/最终标签文件中的 `mid` 也保存为 `float64`；`r_raw`、`r_scaled` 仍为 `float32`。新标签记录 `label_contract_version=2`，统计文件记录对应版本和精度规则。

**Stage5 错误产物仍返回成功。** 故障注入复现了因子表路径不一致、窗口计数错误和时间戳含 NaN 未被拒绝的问题。现在检查全部块与 Stage3 时段元信息、计数和边界是否一致，并在抽样窗口中检查时间有限性、顺序、跨度和相邻间隔。严格模式遇到失败会返回非零退出码，报告明确写入 `ok`、`status` 和检查范围。非严格模式也会如实记录发现的问题。

## 验证结果

- 独立 Linux Python 3.12.14 开发环境下，73 项测试通过；依赖检查、Ruff 正确性检查、Python 编译和示例配置检查通过。
- 每个完整案例包含 8 个时段、3,072 行 CSV、3 个因子，共核对 944 个有效模型窗口。
- 训练集有 1,284 个有效标签，保留 Stage2 原有的至少 1,000 个训练样本要求。
- 核对了重复时间戳、跨分钟、不规则间隔、长时间缺口、报价回退、缺失因子、训练集统计、分片切换和评估尾批。
- 无效输入与破坏产物的测试确认了错误退出或失败报告，而非仅测试正常路径。
- 未运行 TensorFlow/GPU 训练，未验证 Windows 实际运行，也没有 GitHub 托管 CI 成功记录。

详细命令、案例表及检查边界见 [合成验证说明](synthetic_verification.md)，本次观测结果见 [JSON 摘要](verification/v5_synthetic_summary.json)。

## 从 V4 迁移

1. 将 V5 解压到新目录，保留历史配置和产物用于追溯。
2. 可先运行 `python scripts/check.py`，或单独运行 `python scripts/check_synthetic_pipeline.py`。这些命令不需要 GPU 或真实行情。
3. 中间价精度修复改变了标签语义。以后恢复真实数据实验时，从原始 CSV 重新运行 Stage2，然后重建 Stage3–5。不要复制旧标签或只修改标签元信息。
4. `--only-scale` 会拒绝缺少新版精度契约的旧 raw 标签，不能用它把历史舍入标签直接转换成新版标签。
5. 新标签对应的模型需要使用新 `run_name` 重新训练，再生成预测和评估。V5 没有替你执行这些 GPU 步骤，也没有自动迁移历史模型。
