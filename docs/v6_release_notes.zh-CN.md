# V6 技术候选版：第 1、2 项

本版完成标签—模型产物契约和模型组件审阅；尚未进行求职展示内容重写、GitHub 发布或真实 GPU 实验。保留 GPU 训练定位、默认单股票、已有因子输入；Stage0、Stage1.5 和 LightGBM 仍按原有可选边界处理。

## 1. 标签与产物绑定

新增 `src/target_contract.py`，将实际预测区间、事件均值聚合、价格选择规则、不舍入的 float64 中间价、有效性规则、缩放倍数、训练集裁剪值和标定配置写入目标契约。契约的规范 JSON SHA-256 与标签统计文件 SHA-256 随 Stage2 最终标签、Stage3、Stage4、模型和预测传递。

Stage2 原始标签另带定义指纹及源 CSV 指纹，`--only-scale` 会核对定义和源文件，缺文件或口径变化时拒绝继续；它仍需读取源 CSV 字节计算指纹，但不重新解析构造收益。Stage3 会核对每个标签文件，Stage4/Stage5/Stage6 核对当前配置和统计，预测核对模型与打包契约，统计评估及回测核对预测所属模型与目标。仅 horizon 名相同不足以通过校验。

`label_contract_version` 保持 **2**（V5 的收益数学定义未改变），模型契约与预测格式升级为 **2**（新增产物绑定）。V5 原始标签缺少完整定义指纹，不能直接重缩放升级。

迁移必须从原始 CSV 重新构建 Stage2–5，使用新 run_name 重新训练，再生成预测、评估和回测。旧实验结果可以作为独立历史材料保留，不能拼接到本版产物。精确统计文件指纹意味着即使重新生成了数值相同的统计，文件变化也会要求下游重建。

指纹用于发现误用和陈旧文件，不是防篡改签名，也没有为所有大型 pack 数组逐字节建立签名。管线失败后必须检查和重建失败阶段输出，不能把部分写入的输出当作成功产物。

## 2. 模型审阅与修复

- 复现并修复混合精度下因子标准化前降精度、时间输入提前降精度两处问题。
- 指标改用 float64 累积，修复零权重回退到无权重 R²，以及很小收益方差被固定阈值压低 Pearson 的问题；明确常数目标与空权重策略。
- 验证加权 CCC 的数值、梯度及 Keras 编译调用中的 sample_weight，明确限制为单 GPU；MSE、Huber、LogCosh 保留。
- 补充学习率边界校验及零 warmup 支持，保存最终模型前显式恢复最佳验证权重。
- 检查四种损失 × 两种精度策略下的小模型更新和 `.keras`/权重文件往返；增加独立 GPU 合成验收命令。

详见 [模型审阅与验证范围](model_verification.md)。CPU 只执行小规模组件检查，没有启用 CPU 研究训练入口。完整 Stage6 训练、CUDA/cuDNN 和真实数据效果仍须 GPU 实测。
